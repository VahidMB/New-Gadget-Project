# صفحه‌ساز، قیمت نسخه‌دار و عملیات سرور

این راهنما مربوط به `feature/display-studio-production` است و تغییرات راهنماهای ۱۹ و ۲۰ را نیز لازم دارد. این شاخه روی `feature/price-platform-panels` ساخته شده است. کد Firmware و افزونه WordPress تغییر نکرده‌اند. امکانات جدید نمایشگر با نصب سرور به‌تنهایی روی Firmware قدیمی ظاهر نمی‌شوند؛ پیاده‌سازی قرارداد پایین در Firmware لازم است.

## وضعیت تأیید

- آزمون‌های خودکار روی SQLite، کنترل Django، سازگاری migrationها، Ruff و بررسی نحوی JavaScript انجام شده‌اند. تست پشتیبان واقعی SQLite شامل بازیابی و بررسی سلامت دیتابیس است.
- آزمون PostgreSQL هم‌زمان، Docker/Mosquitto، نمایش فارسی روی TFT، توان حافظه/انیمیشن سخت‌افزار، اتصال واقعی WordPress، آب‌وهوا و پیامک هنوز در این محیط انجام نشده‌اند. CI پروژه تست PostgreSQL را اجرا می‌کند؛ نتیجه اجرای آن باید قبل از استقرار بررسی شود.
- نصب مرورگر آزمایشی موفق نشد؛ پیش‌نمایش HTML جای تأیید تصویری مرورگر یا آزمون تاچ واقعی را نمی‌گیرد. این نسخه تا گذر از پذیرش محیط مقصد، آماده ادغام قطعی در production تلقی نمی‌شود.

## مسیرهای پنل

| کار | مسیر |
|---|---|
| پروفایل نمایشگر، شهر، فایل، قالب و تخصیص | `/panel/studio/` |
| ویرایشگر گرافیکی | `/panel/studio/<template_id>/` |
| شبیه‌ساز فقط صفحه نمایش | `/panel/devices/<id>/simulator/` |
| شهر، گردش، لمس و شخصی‌سازی نمودار | `/panel/devices/<id>/display-preferences/` |

| ورود Excel | `/panel/prices/<id>/import/` |

شناسه‌ها از لینک‌های پنل انتخاب می‌شوند. مدیریت صفحه‌ساز در مجوزهای تیکی «مدیریت قالب‌ها»، منابع در «مدیریت منابع» و قیمت در «مدیریت قیمت‌ها» قرار دارد. پشتیبان و تنظیمات عملیات فقط در اختیار مالک سامانه است. مشتری فقط دستگاه‌ها و اطلاعات مجاز حساب خود را می‌بیند.

## ساخت طرح، بدون صفحه نمونه

۱. پروفایل واقعی نمایشگر را با عرض، ارتفاع، اندازه اینچی و سقف عناصر/نقاط نمودار ثبت کنید. برای حالت عمودی، عرض و ارتفاع را مطابق نصب وارد کنید. تا زمانی که Firmware از جلوه پشتیبانی نکرده، تیک درخشش و انیمیشن را فعال نکنید.
۲. تصاویر PNG/JPEG/GIF و فونت TTF خود را بارگذاری کنید؛ قالب خالی با شناسه ثابت ایجاد کنید. فایل‌ها شناسه و SHA256 دارند و از مسیر احرازشده دریافت می‌شوند. فایل تصویری حداکثر ۴ مگابایت، ۱۹۲۰ پیکسل در هر ضلع و ۱۲۰ فریم است؛ این سقف نرم‌افزاری تضمین ظرفیت RAM گجت نیست.
۳. تصویر پس‌زمینه را انتخاب کنید. متن، مقدار، تصویر، ساعت، آب‌وهوا، آخرین پیام مجاز دستگاه، نمودار یا فهرست قیمت را اضافه کنید. مختصات، اندازه، ترتیب لایه‌ها، رنگ، شفافیت، فونت، هاله و ضربان قابل تنظیم است. عنصر را با ماوس جابه‌جا کنید یا مختصات دقیق بدهید. نرخ نمونه بوم، قیمت واقعی نیست.
۴. برای هر مقدار، فیلد یک منبع یا کالای شرکت را انتخاب کنید. یک صفحه می‌تواند چند منبع مستقل داشته باشد. واحد، اعشار، تقسیم برای نمایش و زمان آخرین تغییر را تنظیم کنید. تقسیم نمایش جای تبدیل واحد ذخیره‌شده نیست؛ مثلاً برای ریال به تومان ضریب ۱۰ و برچسب تومان را با هم تعیین کنید.
۵. ذخیره پیش‌نویس با کنترل هم‌زمانی انجام می‌شود؛ نسخه قدیمی نمی‌تواند پیش‌نویس تازه شخص دیگر را بازنویسی کند. انتشار یک snapshot تازه و مستقل می‌سازد. انتشار به‌تنهایی تخصیص دستگاه را تغییر نمی‌دهد.
۶. نسخه را به پلن ساده/pro، شرکت، کاربر یا دستگاه تخصیص دهید. برای یک شناسه قالب، اولویت: دستگاه، کاربر، نزدیک‌ترین شرکت، پلن، عمومی. شرط پلن همیشه اعمال می‌شود. برای قالب ویژه boot/offline/fallback، تنها برنده همان نوع انتخاب می‌شود. صفحه‌ها با ترتیب تخصیص نمایش داده می‌شوند؛ سقف پلن نیز اعمال می‌شود.

قالب‌های `fallback` برای جایگزینی عنصر، `offline` برای صفحه قطع ارتباط و `boot` برای شروع دستگاه‌اند. قالب fallback یک بار ساخته و در عناصر مختلف انتخاب می‌شود؛ نسخه آن در طرح منتشرشده جاسازی می‌شود و تغییر بعدی نیازمند انتشار نسخه جدید صفحه است. در صفحه چندمنبعی خرابی یک عنصر بقیه را از کار نمی‌اندازد. boot می‌تواند لوگو یا GIF تأییدشده باشد. فایل‌ها و قالب‌های آفلاین باید پیش از قطع ارتباط در گجت ذخیره شوند.

مرورگر متن راست‌به‌چپ و فونت سفارشی را نمایش می‌دهد. Firmware باید shaping فارسی، ترتیب متن دوجهته، ارقام، فونت و تصاویر را پیاده کند. پیکسل‌به‌پیکسل بودن مرورگر و TFT بدون بررسی موتور گرافیکی و سخت‌افزار تضمین نشده است. فونت را پیش از انتشار با متن واقعی فارسی روی نمایشگر آزمون کنید.

## منابع و نمودار

اتصال و اعتبارنامه در پنل اتصال‌ها تعریف می‌شوند؛ مقادیر محرمانه در طرح یا پاسخ دستگاه قرار نمی‌گیرند. در صفحه فیلدهای JSON، «کشف مسیر» فقط نام مسیر و نوع مقدار را نشان می‌دهد؛ پاسخ خام و توکن احتمالی بازتاب داده نمی‌شود. مسیرهایی مانند `quote.price` و `items.0.value` پشتیبانی می‌شوند؛ کلید حاوی نقطه قابل انتخاب خودکار نیست.

هر فیلد شناسه ثابت، برچسب، واحد، مسیر، حالت عددی و نگهداری تاریخچه دارد. قیمت لحظه‌ای از روش push موجود و قیمت دوره‌ای از polling موجود می‌آید. اعتبار قیمت و زمان مشاهده از فاصله دریافت مستقل است. timestamp باید ISO8601 همراه offset یا Unix seconds باشد. داده منقضی به عنوان نرخ تازه نمایش داده نمی‌شود؛ تاریخچه لازم برای نمودار حذف نمی‌شود. با تغییر معنای منبع، مسیر یا واحد تاریخی، فیلد جدید ایجاد کنید تا سری‌های نامرتبط مخلوط نشوند.

نمودار خطی/ناحیه‌ای/پله‌ای از تاریخچه واقعی تشکیل می‌شود. کندل به چهار مسیر OHLC، زمان شروع کندل و تایم‌فریم ارائه‌دهنده نیاز دارد؛ داده ساختگی جای OHLC استفاده نمی‌شود. تایم‌فریم مقصد باید مضرب تایم‌فریم منبع باشد. سقف نقاط تا ۵۰۰، سقف خواندن برای هر نمودار ۲۰٬۰۰۰ نمونه در بازه درخواست است؛ افزایش مقیاس نیازمند تجمیع سمت دیتابیس و آزمون بار است. نبود تاریخچه یعنی نمودار خالی. قیمت شرکت فقط نمودار غیرکندلی دارد و تغییر واحد سری را قطع می‌کند.

ادمین نوع‌های مجاز، تایم‌فریم‌های مجاز، تعداد نقاط و قابلیت شخصی‌سازی را تعیین می‌کند. کاربر داخل همین محدوده نوع، تایم‌فریم، تعداد نقاط و رنگ صعود/نزول را انتخاب می‌کند. رنگ زمینه/تصویر و محل رسم بخشی از قالب ادمین است.

## قیمت شرکتی و Excel

Excel باید `.xlsx`، یک شیت، سطر اول عنوان یکتا و حداکثر ۵۰۰۰ کالا، ۳۰ ستون و ۵ مگابایت داشته باشد. فرمول پذیرفته نمی‌شود؛ خروجی نهایی فرمول را به مقدار تبدیل کنید. نگاشت کد پایدار، نام، مبلغ و واحد با پیش‌نمایش و تأیید انجام می‌شود. واحد پیش‌فرض، زمان انتشار و اعتبار قیمت مشخص می‌شود. پیش‌نمایش موقت بعد از ۳۰ دقیقه حذف می‌شود؛ انتشارها و تاریخچه حذف نمی‌شوند.

انتشار یک snapshot کامل است. آخرین نسخه معتبر در سرور می‌ماند؛ انتشار زمان‌دار و اجرای مجدد worker باعث نسخه ناقص یا تاریخچه تکراری نمی‌شود. تأخیر معمول scheduler تا یک دور اجرا، تقریباً ۵ تا ۱۰ ثانیه به‌علاوه زمان صف است؛ تضمین زمان سخت‌بلادرنگ نیست. بعد از اولین انتشار، تغییر اقلام در پنل پیش‌نویس است و باید از «نسخه‌های قیمت» منتشر شود. قبل از اولین انتشار، سازگاری با رفتار قدیمی ویرایش فوری حفظ می‌شود.

برای قیمت اختصاصی نماینده، لیست مستقل با دستگاه‌های مقصد همان نماینده بسازید. پیام اختصاصی نیز از بخش پیام و انتخاب مقصدهای مجاز شرکت ارسال می‌شود. اطلاعات شرکت دیگر در قرارداد نمایش یا شبیه‌ساز مجاز نیست.

گجت قیمت‌ها را صفحه‌ای دریافت می‌کند: حداکثر ۲۰ قلم در هر درخواست، تعداد ردیف واقعی محدود به قالب و ترجیح کاربر. تمام صفحات یک نسخه باید با revision یکسان خوانده شوند. پاسخ 409 یعنی نسخه عوض شده: داده‌های دو نسخه را ترکیب نکنید؛ metadata تازه بگیرید و دسته جاری را در نسخه جدید دوباره بارگذاری کنید. شماره دسته تا حد امکان حفظ و با اندازه لیست جدید تطبیق داده می‌شود. پاسخ قدیمی `/content/` برای سازگاری هنوز لیست کامل را دارد؛ Firmware جدید برای نمایش لیست بلند باید از API صفحه‌ای استفاده کند.

## قرارداد گجت

تمام مسیرها زیر `/api/v1/` هستند و از توکن اختصاصی همان دستگاه در `X-Device-Token` استفاده می‌کنند. توکن را در URL، تصویر یا log ننویسید.

| درخواست | رفتار |
|---|---|
| `GET devices/<external_id>/display/` | manifest با schema=`gadget.display.v1` |
| `GET devices/<external_id>/display/assets/<asset_id>/` | فایل مجاز همان manifest، با SHA256 و ETag |
| `GET devices/<external_id>/price-lists/<id>/page/?revision=...&offset=0&limit=5` | دسته قیمت، نسخه، تعداد کل و offset بعدی |
| `POST devices/<external_id>/display/receipt/` | تأیید دریافت/اعمال نسخه قبلاً ارائه‌شده |

manifest شامل `revision`, `server_time`, `timezone`, `pages`, `special`, `assets`, `controls`, `origins`, `city` است. هر صفحه ابعاد پیکسلی، پس‌زمینه، عناصر، شماره نسخه و شناسه قالب دارد. عنصر داده شامل `data.status`, `data.value`, `data.points`, `expires_at`, `updated_at` و تنظیمات ظاهر است. داده مالی به شکل رشته اعشاری ارسال می‌شود؛ با float محدود Firmware محاسبات مالی انجام ندهید.

`controls`: `page_seconds`, `item_seconds`, `items_per_page`, `automatic`, `resume_seconds`, `touch_short`, `touch_long`. عمل لمس یکی از `next_batch`, `previous_batch`, `next_page`, `previous_page` است. لمس، گردش خودکار را به اندازه resume_seconds متوقف می‌کند. زمان‌های قیمت و صفحه مستقل‌اند. revision طرح با تغییر تنظیمات/تخصیص عوض می‌شود؛ تغییر قیمت revision مستقلی دارد.

نمونه بدنه تأیید:

```json
{"revision":"<64-character revision returned by server>","state":"received"}
```

پس از تعویض موفق تنظیمات در دستگاه، `state=applied` ارسال شود. برای قیمت از `receipt_revision` پاسخ صفحه‌ای استفاده کنید. تأیید «اعمال قیمت» را پس از فعال‌کردن نسخه محلی ارسال کنید، نه صرفاً دریافت یک بسته. سرور هویت و ارائه قبلی را بررسی می‌کند؛ صحت فیزیکی نمایش را از راه دور اثبات نمی‌کند. شبیه‌ساز هیچ رسید واقعی دستگاه تولید نمی‌کند.

MQTT اعلان تغییر را طبق قرارداد قبلی می‌رساند؛ payload تنظیمات جدید `display_contract.fetch_path` دارد. محتوای حجیم و فایل‌ها از HTTP احرازشده گرفته می‌شوند. Firmware قدیمی بدون تغییر می‌تواند API قدیمی را ادامه دهد؛ امکانات صفحه‌ساز جدید به renderer سازگار نیاز دارد. WordPress همچنان قرارداد امضاشده راهنمای ۱۱/۱۹ را استفاده می‌کند؛ افزونه دوست شما تغییر داده نشده است.

## شبیه‌ساز

فقط صفحه نمایش را نشان می‌دهد. داده واقعی از همان `build_manifest` و مجوزهای دستگاه می‌آید. حالت آزمایشی صریحاً برچسب دارد. می‌توان صفحه/دسته، لمس کوتاه/بلند، شروع، قطع اینترنت، انقضای همه داده‌ها و خرابی یک عنصر را بررسی کرد. در قطع اینترنت، قالب offline در صورت وجود اولویت دارد؛ وگرنه داده cache فقط تا انقضا نمایش داده می‌شود. شبیه‌ساز مرورگر، مصرف RAM، زمان رسم و درایور TFT را شبیه‌سازی نمی‌کند.

## عملیات، پشتیبان و پیامک

در compose guided، Redis صف دارای AOF است و cache گذرا Redis جداگانه دارد. صف پشتیبان/پیامک در دیتابیس ذخیره می‌شود؛ `operations` زمان‌بندی و هشدار، و `backups` پشتیبان طولانی را مستقل اجرا می‌کند. قطع broker جلوی اجرای این دو worker را نمی‌گیرد. Celery نیز انتشار موعدرسیده را بازیابی می‌کند. کارهای ناموفق با تأخیر تا پنج بار تکرار می‌شوند و مالک پس از رفع علت می‌تواند «تلاش دوباره» را بزند. اجرا دقیقاً یک‌بار در سامانه توزیع‌شده تضمین نمی‌شود؛ پشتیبان/انتشار idempotent هستند و سرویس پیامک باید Idempotency-Key را پشتیبانی کند.

پشتیبان دستی/خودکار شامل dump دیتابیس، فایل‌های media، کلیدهای runtime و کلیدهای تنظیم‌شده برنامه است. فایل فقط از پنل مالک دانلود می‌شود. فایل `.env.guided` و تنظیمات reverse proxy را نیز جداگانه و محرمانه نگه دارید. با کلیدهای داخل آرشیو می‌توان اسرار را بازیابی کرد؛ آن را در مسیر عمومی قرار ندهید. آرشیو روی همان سرور ذخیره می‌شود؛ برای خرابی دیسک باید نسخه دانلودشده خارج سرور نگه دارید. حذف خودکار پشتیبان و تاریخچه حیاتی فعال نشده است. dump دیتابیس سازگار است اما snapshot اتمی مشترک دیتابیس و کل filesystem نیست؛ فایل‌های منتشرشده را بیرون سامانه جابه‌جا/بازنویسی نکنید.

پیامک فعلاً adapter عمومی HTTPS POST JSON با دو فیلد گیرنده/متن، auth header و متن قابل تنظیم است. اتصال در «اتصال‌ها» و نگاشت در «عملیات» تعیین می‌شود؛ هیچ ارائه‌دهنده‌ای از پیش فعال نیست. APIهایی با قالب متفاوت نیاز به adapter خواهند داشت. پذیرش HTTP معادل تحویل SMS نیست. هشدار هنگام تغییر وضعیت ثبت می‌شود تا یک خطا پشت‌سرهم پیامک نسازد. خرابی کامل میزبان/دیتابیس نمی‌تواند از همان میزبان پیامک بفرستد؛ پایش خارجی برای آن لازم است.

برای آب‌وهوا، اتصال provider، URL شامل `{lat}` و `{lon}`، مسیر دما/شرح، واحد و دوره دریافت را تنظیم کنید. شهرها در صفحه‌ساز ثبت می‌شوند و کاربر از منو انتخاب می‌کند. مختصات خودکار یا GPS فرض نشده است. اعتبارنامه به همان origin تعریف‌شده اتصال محدود است.

## ارتقا و پذیرش روی سرور

ابتدا backup قابل بازیابی از نسخه قبلی بگیرید. مسیر پروژه، `.env.guided` و نام پروژه compose را حفظ کنید؛ `down -v` اجرا نکنید. اگر تغییر محلی دارید پیش از switch بررسی/ثبت کنید؛ reset اجباری نکنید.

```bash
git fetch origin
git switch feature/display-studio-production
git pull --ff-only origin feature/display-studio-production
sudo docker compose --env-file .env.guided -f docker-compose.guided.yml --profile public build
sudo docker compose --env-file .env.guided -f docker-compose.guided.yml --profile public stop api worker beat operations backups collector broker_config
sudo docker compose --env-file .env.guided -f docker-compose.guided.yml --profile public up -d
sudo docker compose --env-file .env.guided -f docker-compose.guided.yml ps
sudo docker compose --env-file .env.guided -f docker-compose.guided.yml logs --tail=100 api operations backups worker beat
```

فقط بعد از build موفق مرحله توقف را اجرا کنید. migrationهای ۰۰۱۵ تا ۰۰۱۸ جداول/فیلدهای جدید را اضافه می‌کنند. ورود به پنل قبلی حفظ می‌شود. نصب خام از `sudo make guided` و راه‌انداز گرافیکی قبلی استفاده می‌کند. استقرار بدون دامنه از SSH tunnel روی localhost استفاده کند؛ دامنه را بعداً در تنظیمات ارتباطی تعیین کنید. composeهای قدیمی برای امکانات جدید worker پشتیبان/عملیات ندارند؛ این راهنما مشخصاً guided است.

در محیط آزمایشی مقصد این موارد باید تأیید شوند: مهاجرت از backup واقعی؛ restore PostgreSQL در دیتابیس جدا و بازیابی یک فایل/اعتبارنامه؛ دریافت API با توکن دو دستگاه از دو شرکت و رد دسترسی متقاطع؛ انتشار لیست بیش از ۱۰۰ قلم با قطع Redis/راه‌اندازی دوباره worker؛ رد قیمت منقضی؛ نمودار OHLC منبع انتخابی؛ قطع یک منبع در صفحه چندمنبعی؛ اعمال نسخه و receipt از Firmware؛ فارسی/فونت/تصویر/درخشش روی TFT واقعی؛ لمس و گردش؛ اتصال امضاشده WordPress؛ دریافت یک پیامک آزمایشی از provider انتخابی؛ بررسی بار هدف و فضای تاریخچه. قبل از عبور از این پذیرش‌ها روی مشتری واقعی عرضه نشود.
